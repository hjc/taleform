Today's output is not wrong; the order has always been implicit, and a mistake would fail silently.

BUILDERS is a flat array, and build() runs it front to back. The comment on the array is the only statement of what depends on what.

/** * Every builder, in the order they run. A builder may read what an earlier one emitted, so the * order is a dependency list: schema validates first, then notes are rewritten, then the views * that summarise them (mission note regions, maps) are built last. */ export const BUILDERS: Builder[] = [schema, navigation, awards, resume, ledger, adventureMap]; for (const builder of builders) { const ctx: BuildContext = { index, options, read: (path) => overlay.get(path)?.content ?? preload.get(path), emit: (path, content, opts?: EmitOptions) => { const entry: { content: string; builder: string; same?: EmitOptions["same"] } = { content, builder: builder.id }; if (opts?.same) entry.same = opts.same; overlay.set(path, entry); }, problem: (severity: Severity, message: string, path?: string) => { const p: Problem = { builder: builder.id, severity, message }; if (path) p.path = path; problems.push(p); }, }; await builder.run(ctx); }

Builder (src/core/builder.ts lines 42-46) is { id, description, run }. It has no field to declare a dependency, and the engine validates neither the list it is handed nor the ids. The cross-reads that exist today:

Measured with a scratch script that ran build() over a small in-memory mission (one act, two beats, one with an awards entry; a mission note with resume and xp regions) under all 720 permutations of the six builders:

  • Every permutation produced files byte-identical to the registered order, because the shared-path builders read the overlay and edit disjoint text. In that fixture the array order carries no output dependency.
  • 540 of 720 permutations attribute at least one changed path to a different builder in Change.builder, because overlay.set keeps only the last emitter of a path.
  • Not measured: schema-problem paths, --mission filtering, CRLF notes, or a builder that replaces a file instead of patching it.
