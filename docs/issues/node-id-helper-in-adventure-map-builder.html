issue src/builders,src/core,test quality developer silent abstraction-spotting shape I on the roadmap's Arc and Campaign Map builders medium low small p3 The deterministic canvas node-ID helper nid() is exported from the Adventure Map builder, so the Arc and Campaign Map builders would have to import it from a sibling builder or copy it, and a diverging copy would churn that map's IDs on every build. It has lived there since the typed story model landed. Nothing fails today: only one canvas builder exists. A duplicate that drifts is reported by nothing, because each map stays self-consistent.

nid hashes its parts with sha1 from src/core/sha1.ts and keeps 16 hex characters. The helper is generic, but it is defined and exported beside Adventure Map layout code, and test/core.test.ts imports it from the builder. Measured with grep -rn "\bnid\b" src test: one definition, 30 call sites in adventureMap.ts (one is the edge id at line 80), and one test import (test/core.test.ts:3). No other module uses it.

export const nid = (...parts: string[]) => sha1(parts.join("|")).slice(0, 16);

The roadmap names Arc Map and Campaign Map builders (docs/roadmap.md, not yet designed). Each needs stable node IDs, since CLAUDE.md says IDs "must stay stable across builds, or maps churn". It would either import nid from ../builders/adventureMap (a builder-to-builder dependency) or copy it. Two copies would hold one identity rule in two places: the separator, the 16-character slice and the hash input shape.

Related, not the subject: the same file also holds the generated marker (MARK, line 20, value "adventure-map") and the hand-item merge (lines 288-293). They are shape I of the abstraction-spotting skill too, a primitive living in its first consumer. This issue covers nid only.
