issue src/builders,src/core,src/cli,src/plugin portability adopter code audit of src/ for adopter portability medium low large p3 Taleform's builders assume the note shapes, prose markers, glyphs, rules tables and locale of the developer's own campaign vault, with no way to change any of them, so an adopter whose notes differ gets a refused map, silently skipped cross-checks or output in the wrong shape. The assumptions have been literals since each builder was written; most fail loudly (a map error, a missing-region warning), a few silently (an unparsed XP line, a retired-name collision).

Every convention below is a literal in src/. The one setting the plugin has is autoBuild; the CLI has no config file; a mission's frontmatter carries only party-size, party-xp and handoff. There is nowhere an adopter could state a different convention.

interface Settings { /** Rebuild shortly after any note's metadata changes. */ autoBuild: boolean; } const DEFAULTS: Settings = { autoBuild: true };

Candidate routes: mission (frontmatter on the mission note, so two missions in one vault can differ), config (a vault-level plugin setting or config file) and fixed (keep the literal and document it as the contract). They are candidates for the PRD, not decisions.
